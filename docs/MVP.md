# PowerQED MVP

## Goal

Prove that PowerQED can produce trustworthy energy evidence for one real site.

## Timeline

3–4 months.

## Budget

$170–200K.

## Team

- 2 Senior C# Engineers
- 1 Senior C++ Engineer
- 1 Senior MS SQL / Data Engineer
- DevOps shared across team

All team members handle DevOps responsibilities.

Team can be doubled with full-time developers if required.

## Existing Platform

C# Blazor operational platform is reused.

First demo within 1–2 weeks: map, documents, reports, SLA, chat.

Blockchain integration comes after the demo.

This reduces risk and accelerates the pilot.

## Scope

One data center campus.

One revenue-grade facility meter.

One solar or wind source.

One BESS.

One backup generator.

15-minute or 1-hour interval.

Signed canonical events.

Device and gateway identity.

Measurement Boundary.

Merkle batches.

Ethereum commitment.

Deterministic CFE policy engine.

Evidence Graph.

Verifiable audit package.

Web verifier.

## Deliverable

PowerQED Verification Receipt:

- Claim ID
- Policy
- Period
- Consumption
- Matched generation
- Certificates
- Evidence sources
- Assurance profile
- Boundary status
- Proof root
- Ethereum anchor
- VERIFY

## What is NOT in MVP

- Custom ZK circuits
- Decentralized verification network
- Full EV fleet integration
- Multi-site aggregation
- EnergyTag integration

These are Phase 2+.

## First Customers

Not hyperscalers.

Focus on:

- AI data center developers
- Colocation providers
- GPU cloud providers
- Independent data center operators
- Renewable suppliers servicing data centers
- Battery / VPP operators
- Energy retailers selling 24/7 CFE

## Definition of Done

One real site produces trustworthy evidence.

A third party can verify the Verification Receipt.

At least one partner confirms the evidence is useful for settlement or audit.
